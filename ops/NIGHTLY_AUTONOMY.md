# HABIT QUEST — 夜間自動検査と安全なAI開発

更新：2026-11-23

## 導入した検査

- 毎日 **02:37 JST**（前日17:37 UTC）に GitHub Actionsの全回帰テストを実行する。
- main へのすべての push と main 宛のすべての PR で自動テスト。旧設定では habit-groups.js など単独更新時にmainのCIが起動しない可能性があった。
- 実行前に node scripts/deployment-audit.mjs --local でHTML参照ファイル、Service Workerの事前キャッシュ資産、実ファイルの存在をチェック。
- 夜間・mainでの手動実行時には、GitHub Pagesで実際に配信されている index.html、Service Worker、事前キャッシュ対象のすべてのファイルをGitHub mainの内容と読み取り比較する。HTTP失敗・ファイル不一致を検出する。
- 検査にサービスロールキー、Ouraトークン、ユーザーの習慣記録を使用しない。本番Supabase DBへの書き込みはしない。
- Actionsのログと失敗通知で検査結果を確認する。スケジュールの起動はGitHub側で遅延・スキップされ得るため、毎晩の実行が100%保証されるわけではない。

## 検査とAI実装の区別

このGitHub Actionsは **自動検査** であり、AIが自律的に機能を設計・追加するものではない。
AIによる作業を継続させるには、別途ChatGPTのスケジュールされたタスクやCodex/Work等の実行基盤と、GitHubへのアクセス・実行枠の確認が必要。

AIが実装する場合の原則：

1. HANDOFF.md と ROADMAP.md、現在のソースと既存テストを読み込む。
2. 既存の習慣チェック、XP起算日・Lv.50、Oura・Supabase Auth、通貨を保持する。
3. 低リスク修正のみ作業ブランチへ。PRとCI結果を記録し、未試験項目は明示する。
4. ユーザー記録の削除、認証・DBの破壊的変更、課金・有料プラン変更、本番データ書換えは無断実行しない。
5. テスト失敗時は原因を追跡。安全な修正を確認できなければ本番反映を行わない。
6. プライベートな記録・トークン・環境変数値を公開IssueやGitHubログに出さない。

## 異常時の初動

| 症状 | 推定原因と確認順 |
| --- | --- |
| local inventoryが失敗 | HTML参照名、実ファイルの欠落、sw.jsのASSETS登録漏れ |
| 既存テストが失敗 | リグレッション。失敗テスト→変更差分→仕様の順に検証 |
| 公開ファイル不一致 | GitHub Pagesのデプロイ未完了・CDN遅延・古い配信。Pages workflowの成功履歴を確認 |
| ページHTTP失敗 | GitHub Pages側の障害、公開設定、ネットワーク一時障害 |
| 定期実行が行われない | GitHubのスケジュール遅延、公開リポジトリの60日無活動による自動停止、Actions設定 |

## 未解決・別途受入

- 実PC/スマホ間でのユーザー本人による双方向同期・オフライン再送
- Oura実トークン更新・歩数反映
- PWAアップデート時のスマホ操作と通知の実機テスト
- 一般公開時の新規登録・退会・認証・RLSの受入
- AIが夜間に安全なPRを作成する自動実行の動作実証

GitHub Pages配信のバイト単位検査は、認証後の動作、操作性、Oura実API接続を保証しない。
